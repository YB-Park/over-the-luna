# v1.1 baseline evidence — 2026-08-19

This file records observed behavior from controlled runtime probes. It is evidence, not a design
specification.

## Probe 001 — handoff-regression analysis

### Purpose

Verify that the checked-out plugin can run through GitHub Copilot itself and capture one concrete
example of the released routing policy before changing that policy.

The probe was intentionally read-only and asked Over the Luna to determine how this repository
validates custom-agent metadata and identify the smallest regression check for a handoff target that
does not resolve to an actual custom-agent name.

### Runtime

- GitHub Actions, personally-owned `YB-Park/over-the-luna` repository.
- GitHub Copilot CLI 1.0.80.
- Plugin loaded from the checkout with `--plugin-dir=.`.
- Main agent selected by the Copilot CLI plugin-qualified ID
  `over-the-luna:over-the-luna`.
- Model: `gpt-5.6-luna`.
- Write/shell tools disabled; no repository mutation occurred.
- OTel content capture disabled.
- Result: exit code 0.

The CLI and VS Code use different identifiers in at least one important place: Copilot CLI agent
selection requires the plugin-qualified ID, while current VS Code handoff switching resolves a
custom agent through its loaded agent name. Tests must not assume the two identifier surfaces are
interchangeable.

### Observed route

The first visible routing decision was:

`Mode: SIMPLE — direct Luna`

No subagent was invoked.

After declaring SIMPLE, Main performed three repository-wide glob operations:

- `**/*` — 27 paths in this small repository;
- `**/*agent*` — all 10 agent definitions;
- `**/*test*` — the two test files.

It then read five files in parallel:

- `scripts/validate_plugin.py`;
- `tests/test_runtime_contract.py`;
- `plugin.json`;
- `.github/workflows/validate.yml`;
- `agents/over-the-luna.agent.md`.

The answer was correct: the newly added
`RuntimeContractTests.test_custom_handoffs_resolve_to_exact_agent_names` is already the minimal
regression check.

The first version of `scripts/analyze_otel.py` incorrectly attributed the plugin-qualified root agent

### Interpretation

This is **one data point, not proof that SIMPLE is globally over-selected**.

The repository is only 27 files, and the task itself was bounded. It is therefore defensible that a
model might view the entire repository as locally inspectable.

However, the trace is still important because the current Main contract says that SIMPLE should use
focused local inspection and should promote when exploration materially broadens. In this sample,
Main committed to SIMPLE before inspecting locality, then performed repository-wide discovery and
five reads without reconsidering the route.

That supports a narrower hypothesis worth testing:

> The current policy may anchor too strongly on the initial `SIMPLE — direct Luna` classification,
> so the later promotion rule does not reliably fire when inspection expands.

This is distinct from saying "SIMPLE is bad" or "more subagents are always better."

### Consequence for v1.1 research

Do not lower a numeric SIMPLE threshold yet.

Instead compare the released policy against candidate policies on representative cases where:

- the task is locally clear and should remain direct;
- the eventual edit is simple but discovering the correct pattern requires broader exploration;
- implementation can be direct but a non-trivial result deserves a fresh independent review;
- a consequential assumption warrants a distinct challenge;
- a concrete failure warrants Recovery.

The primary question is whether another Luna call buys useful isolation or assurance, not whether it
increases the subagent-call count.

## Infrastructure lessons from Probe 001

The probe setup itself exposed several useful contract facts:

- Copilot CLI 1.0.80 enforces a minimum accepted `--max-ai-credits` ceiling of 30. The ceiling is not
  a target spend; it is only a hard stop supported by the CLI.
- shell pipelines around Copilot must use `set -o pipefail`; otherwise a failing Copilot command can
  be masked by a successful `tee`.
- local plugin agent selection in Copilot CLI uses a plugin-qualified ID.
- paid runtime probes must not run on every push/PR. The probe workflow is manual-only after this
  baseline run.
- CLI probes are useful for plugin loading, routing behavior, tool traces, and token/call telemetry,
  but they do not replace authenticated VS Code checks for handoff UI, selected-tool inheritance,
  or other editor-specific behavior.
